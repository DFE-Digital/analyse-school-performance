**What do we want to find out through data tracking?**

Prioritising User needs based on data
- Demonstrating which areas of the service are used most
- Identifying high effort, low use areas

Identifying gaps in the Service
- Which guidance links are used most? This indicates that something isn't clear.
- Users pulling out data to use in other settings - what data are they pulling out? What format?

**What data is currently tracked?**
- Views
- Users
- Views per User
- Average engagement time
(all per page ie school)

**Ideas for User metrics:**
Proof of providing value:
- Increase in number of schools which has at least one User using ASP
- Increase in how often a User returns to ASP
- Monitor number of Users only using service to access IDSR link

Get the data they're looking for quickly and easily
- Decrease in Users only getting as far as entry page
- Monitor pogoing - where a User goes to a page and then clicks back immediately
- What pages have the most negative behaviours (pogoing, few interactions)

Use tools to explore data further, gaining more value
Spot areas for improvement or to share best practise
- Which pages show the most interaction with data - monitor hovers, click to convert to table etc
- Monitor pages with highest traffic/interaction to explore if we could provide further value

How long a User spends on ASP isn't necessarily a good thing! Quick journeys show they were able to find what they needed easily - but they also mean the User isn't accessing everything that may be of value to them.

**Questions**
- Is there a difference how Primary and Secondary interact with the site?
- Highlight path to IDSR Users and remove from data
- Do people click on the help buttons? What do they need help on most?
